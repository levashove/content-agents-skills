# Cloud / IaaS Translation Dictionary

> ⚠️ **Черновик.** Словарь собран без вычитки редактором-терминологом: применяй как справочник, при расхождении с каноном (`references/translation-glossary.md` → «Общая таблица») и с готовыми словарями выигрывают они. Спорные ряды помечены «проверить» в комментарии.

Словарь для переводчиков технических статей об облачных платформах: IaaS/PaaS, виртуализация, хранилища, тарификация, миграция, FinOps. **Не догма** — отражает узус русскоязычного облачного сообщества (документация провайдеров, Хабр, 12factor.net на русском, OpenStack RU) на 2026 год. Если автор оригинала использует устоявшийся в его команде вариант, и он не противоречит словарю — оставляй авторский.

Границы с соседними словарями: Kubernetes и оркестрация контейнеров — `k8s-translation-dictionary` (его термины здесь не дублируются); Terraform, Ansible, CI/CD и IaC — `devops-translation-dictionary`; VPC, подсети, security group, floating IP, балансировка и CDN — `networking-translation-dictionary`; IAM, шифрование, комплаенс — `security-translation-dictionary`; резервное копирование и репликация БД — `databases-translation-dictionary`. При пересечении термин переводится по словарю домена-владельца.

## Принципы

1. **Модели обслуживания — аббревиатурой в оригинале.** `IaaS`, `PaaS`, `SaaS`, `FaaS`, `DBaaS` — не транслитерируются («ИааС» не существует). При первом упоминании допустима расшифровка рядом: «IaaS (инфраструктура как услуга)» — это расшифровка аббревиатуры, а не толкование термина.
2. **Русское слово по умолчанию, англицизм — только там, где он реально узус техтекста.** `virtual machine` → «виртуальная машина», `availability zone` → «зона доступности», `quota` → «квота». «Инстанс», «бакет», «снапшот», «бэкап» — устоявшиеся англицизмы Хабра и документации провайдеров; в клиентских текстах (лендинги, рассылки) — русское слово: «виртуальная машина», «резервная копия». В одном тексте — один вариант.
3. **Имена проектов OpenStack, продуктов виртуализации и облачных сервисов — оригинал.** `Nova`, `Neutron`, `Cinder`, `Glance`, `Keystone`, `KVM`, `QEMU`, `VMware vSphere`, `Amazon S3` — как имена собственные, с той же капитализацией, что в проекте; не склоняются и не транслитерируются.
4. **Тарифные модели — переводятся, кроме собственных названий тарифов.** `pay-as-you-go` → «оплата по факту потребления», `reserved instance` → «зарезервированный инстанс», `spot instance` → «спотовый инстанс». Названия конкретных тарифов провайдера (`Savings Plans`, `Free Tier` как имя программы) — оригинал.
5. **Термины FinOps — русское слово там, где оно есть; `showback` / `chargeback` — оригинал.** «Оптимизация затрат», «распределение затрат», «бюджет» — переводятся; `showback`, `chargeback`, `rightsizing` — оригинал, при первом упоминании узкого термина — сноска переводчика.
6. **При первом упоминании узкого термина — сноска переводчика, не скобки.** В тексте — `landing zone[^1]`, `steal time[^2]`; в конце материала — `[^1]: Landing zone — базовая настроенная среда в облаке (аккаунты, сеть, доступы), с которой начинается миграция. — Прим. перев.` Дальше — термин без сноски. Три исхода для любого термина: русское слово, оригинал, оригинал со сноской.
7. **Поля API, параметры CLI и значения конфигурации — оригинал в backtick.** `flavor`, `user_data`, `availability_zone`, `--image` — как в коде, не переводятся, не склоняются.

## Раздел 15. Типовые ошибки переводчика облачных статей

### 1. Транслитерация аббревиатур моделей обслуживания

```
✗ «ИааС-провайдер», «СааС-решение»
✓ «IaaS-провайдер», «SaaS-решение»
```

### 2. Калька «поставщик облака»

```
✗ «выбрать поставщика облака»
✓ «выбрать облачного провайдера»
```

### 3. Смешение «инстанс» и «виртуальная машина»

В одном тексте — один вариант. Не смешивай:

```
✗ Мы подняли три инстанса. Виртуальные машины получили по 4 vCPU. Инстансы подключены к сети.
✓ Мы подняли три инстанса. Инстансы получили по 4 vCPU и подключены к сети.
```

### 4. «Корзина» и «ведро» вместо бакета

```
✗ «загрузить файл в корзину S3»
✓ «загрузить файл в бакет S3»
```

### 5. Перевод имён проектов OpenStack и полей API

```
✗ «сервис Нова», «настроить флейвор в поле „конфигурация“»
✓ «сервис Nova», «задать `flavor`»
```

### 6. «Латентность» и «троттлинг»

```
✗ «низкая латентность диска», «троттлинг запросов к API»
✓ «низкая задержка диска», «ограничение частоты запросов к API»
```

### 7. Склонение несклоняемых

```
✗ «в OpenStack'е», «на KVM'е», «через cloud-init'а»
✓ «в OpenStack», «на KVM», «через cloud-init»
```

### 8. Калька «является» и «позволяет»

```
✗ «Зона доступности является изолированным дата-центром»
✓ «Зона доступности — изолированный дата-центр»

✗ «Автомасштабирование позволяет добавлять инстансы»
✓ «Автомасштабирование добавляет инстансы при росте нагрузки»
```

### 9. Рекламные формулы вместо терминов

```
✗ «плати только за то, что используешь» (как термин)
✓ «оплата по факту потребления» / «pay-as-you-go»
```

### 10. Описание термина в тексте вместо сноски

```
✗ «landing zone — то есть базовая настроенная среда в облаке — создаётся первой»
✓ «landing zone[^3] создаётся первой»
   [^3]: Landing zone — базовая настроенная среда в облаке, с которой начинается миграция. — Прим. перев.
```

## Раздел 16. Чек-лист переводчика облачной статьи

Перед сдачей литерального перевода пройди по чеклисту:

- [ ] **IaaS / PaaS / SaaS / FaaS / DBaaS** — латиницей, расшифровка при первом упоминании
- [ ] **Имена проектов OpenStack и продуктов виртуализации** (Nova, Neutron, Cinder, Glance, Keystone, KVM, QEMU, VMware) — оригинал, не склоняются
- [ ] **Поля API и параметры CLI** (`flavor`, `user_data`, `availability_zone`) — не переведены, в backtick
- [ ] **Транслитерация согласована** — один вариант на текст: «инстанс» или «виртуальная машина», «снимок» или «снапшот», «диск» или «том»
- [ ] **Канон Общей таблицы соблюдён** — задержка, пропускная способность, ограничение частоты запросов, аварийное переключение, выделение ресурсов
- [ ] **Термины соседних доменов** — по их словарям: Kubernetes (k8s), Terraform и CI/CD (devops), VPC и балансировка (networking), IAM и шифрование (security)
- [ ] **Узкие термины** (landing zone, steal time, showback, chargeback, erasure coding) — оригинал со сноской переводчика «— Прим. перев.» при первом упоминании, без описаний в тексте
- [ ] **Тарифные модели** — переведены (оплата по факту потребления, зарезервированный, спотовый), имена тарифных программ — оригинал
- [ ] **Числа и единицы** — `10 000` (пробел), `99,95 %` (запятая, пробел перед %), `5 ГБ`, `100 мс`, `2 vCPU`
- [ ] **Калек избегли** — нет «является», «позволяет», «осуществляет», «производит», «поставщик облака»
- [ ] **Кавычки** — «ёлочки», внутри — „лапки“

## Раздел 17. Когда термин имеет несколько устоявшихся переводов

Если в русскоязычном облачном сообществе нет единого варианта (например, `instance` → «инстанс» / «виртуальная машина», `volume` → «диск» / «том», `managed service` → «управляемый сервис» / «managed-сервис»), действуй по приоритету:

1. **Смотри на оригинал.** Если автор пишет разговорно («spin up a box», «VMs»), сохраняй уровень формальности; если это документация — формальный вариант.
2. **Смотри на площадку.** Хабр и блоги провайдеров — «инстанс», «снапшот», «бакет», «managed-сервис». Документация и клиентские тексты — «виртуальная машина», «снимок», «управляемый сервис».
3. **Смотри на целевого провайдера.** Если в статье речь о конкретной платформе, бери термины из её русскоязычной документации (там «диск» или «том», «каталог» или «проект» — уже решено).
4. **Если переводишь в первый раз — бери канонический (первый) вариант словаря.**
5. **В одном тексте — один вариант.** Это правило важнее любого «правильного» выбора.

## Раздел 18. Что делать с новыми терминами

Если в статье встречается термин, которого нет в этом словаре:

1. **Проверь Общую таблицу** — `references/translation-glossary.md`, затем соседние словари (k8s, devops, networking, security, databases): термин может принадлежать им.
2. **Проверь русскоязычную документацию провайдеров** — разделы «Глоссарий» и «Концепции» у крупных российских облаков и русская локализация AWS.
3. **Проверь документацию OpenStack** — https://docs.openstack.org/ (глоссарий проекта) и переводы на Хабре.
4. **Проверь 12factor.net на русском** — https://12factor.net/ru/ для терминов cloud-native.
5. Если нигде нет — оставь **в оригинале**; если термин узкий, при первом упоминании дай сноску переводчика: `Термин[^N]` + `[^N]: Термин — что это. — Прим. перев.` Помета «устоявшегося перевода нет» — в отчёт проверяльщику, не в текст.
6. Не придумывай свой перевод — это вносит непоследовательность в экосистему.

Все новые термины, которые встретились в работе, проверяльщик (`translation-verifier`) может предложить добавить в словарь. Решение о добавлении — за оркестратором и редактором-терминологом, который вычитывает этот черновик.
