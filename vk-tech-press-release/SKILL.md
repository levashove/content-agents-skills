# Пресс-релиз VK Tech (чат-версия конвейера)

Композитный скилл: фирменная структура, эталонные релизы и редполитика
пресс-релизов VK Tech в одном процессе для работы в чате. Этот файл —
маршрутизатор: жёсткий минимум и порядок шагов здесь, детали — в `references/`
(открывай по карте ниже, а не все сразу).

**Границы применения.** Скилл — для написания пресс-релиза по фактуре
пользователя. В чате нет изолированного ресёрчера и фактчекера конвейера — их
заменяет самопроверка шага 7; это честное ограничение, а не эквивалент полного
конвейера.

## Жёсткий минимум (действует всегда, даже без открытия справочников)

1. **Факты — только из фактуры пользователя.** Продуктовые цифры, сертификации,
   сроки и условия не выдумываются и не «вспоминаются»: нет в предоставленных
   материалах — спроси или поставь маркер `[NEEDS_FACTCHECK: что проверить]`.
   Расхождение фактуры с известными фактами — флаг, а не молчаливый выбор.
2. **Канон структуры 2026:** дата → заголовок → **лид курсивом** → тело (2–3
   абзаца) → [цитата партнёра / клиента] → **цитата спикера** → [цитата автора
   исследования] → [финальная строка] → [бойлерплейт]. Релиз — **250–400 слов**;
   больше 450 — сокращай, а не сдавай.
3. **Лид — курсивом, 2–3 предложения, до 45 слов, с выгодой для заказчика.**
   Цифра — только если она и есть новость (сумма, грант, кратность, доля);
   рыночных цифр и ролей аудитории в лиде нет. Повод/площадка анонса — в лиде,
   если новость привязана к событию.
4. **Цитата открывается тезисом** (проблема заказчика / сдвиг / «мы»), затем
   что снимает продукт и что это меняет. 40–65 слов. Аналитическая цифра — не
   больше одной на релиз, только в цитате и с источником внутри. Спикер назван,
   должность — канон из фактуры, не из памяти. Партнёрство, кейс, исследование —
   вторая цитата обязательна (текст или пометка на согласование).
5. **Без буллитов в теле релиза** — сплошной текст. Сложные термины
   расшифровываются при первом упоминании: релиз читают журналисты.
6. **Сравнительная метрика — всегда с базой сравнения.** «Ускоряет на 15%» без
   «по сравнению с {база}» — искажение. Сертификации — точно и дословно.
7. **Один заголовок в выдаче, чистое тело.** Варианты заголовка/лида, источники
   цифр и открытые вопросы живут в служебном блоке после `---`, в тело релиза не
   попадают; в теле нет сносок, H2, плейсхолдеров, конкурентов по имени и
   англицизмов (SMB, as-is, on-prem, PAYG). Без запрещённых слов и ИИ-паттернов.

## Процесс

### Шаг 1. Вход

Собери от пользователя: инфоповод, тип релиза (продукт / обновление /
партнёрство / совместимость / клиентский кейс / исследование / мероприятие),
фактуру (цифры с базой сравнения, сертификации, сроки, условия), спикера с
точной должностью, вторую сторону для цитаты, повод/площадку анонса. Чего-то нет — спроси одним
сообщением списком, не по одному.

### Шаг 2. Заголовок

Предложи 3–5 вариантов по формуле `[Субъект: VK Tech | продукт | клиент] +
[глагол] + [продукт/суть] + [для кого/зачем]`, ≤ 100 символов, без превосходных
степеней — и дай выбрать. Цифра в заголовке — только результат или масштаб.
Формулы и эталонные заголовки → `references/press-release-knowledge.md`.

### Шаг 3. Лид

К выбранному заголовку — 2–3 варианта курсивного лида: с цифрой-новостью
(если она есть), без цифры с выгодой, с поводом анонса → на выбор. Требования к лиду →
`references/press-release-standards.md`.

### Шаг 4. Тело

2–3 абзаца сплошным текстом: что это и как работает (термин расшифровать один
раз) → что меняется для заказчика (одно число с базой) → отрасли и сценарии;
соответствие требованиям — здесь, как факт продукта. Без рыночного контекста,
конкурентов, идентификаторов и версий. Голос делового релиза и запреты →
`references/press-release-content-quality.md`.

### Шаг 5. Цитата спикера

Открытие тезисом, 40–65 слов, формат: *«{текст}»*, — комментирует **{Имя
Фамилия}, {должность}**. Для партнёрства, кейса, исследования — вторая
цитата (партнёр / клиент первым, автор исследования вторым). Формулы и эталонные цитаты →
`references/press-release-knowledge.md`.

### Шаг 6. Финал

Финальная строка — только если есть факт (условия и сроки, доступность
поставки, ссылка на документацию или отчёт) + бойлерплейт по типу релиза
отдельным блоком (каталог бойлерплейтов → `references/press-release-knowledge.md`).
Проверь объём: 250–400 слов без бойлерплейта.

### Шаг 7. Самопроверка

Пройди чек-лист из `references/press-release-standards.md`. Стоп-слова и
замены → `references/press-release-content-quality.md` и
`references/content-quality.md`; продуктовые названия →
`references/press-release-brand-terminology.md`, `references/brand-terminology.md`
и `references/vk-tech-redstandards.md` (типографика); атрибуция цитат и чужих
исследований → `references/source-attribution.md`; чистка ИИ-паттернов →
`references/ai-pattern-cleanup.md`.

### Шаг 8. Сдача

Отдай релиз + служебным блоком после `---`: источники цифр, альтернативные
заголовок и лид, оставшиеся маркеры `[NEEDS_FACTCHECK]` (если есть) и что
человеку проверить руками (должность спикера, продуктовые цифры, сертификации,
цитата партнёра). Релиз с маркерами не выдавай за
готовый к публикации.
