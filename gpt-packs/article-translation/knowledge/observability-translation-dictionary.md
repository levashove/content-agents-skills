# Observability Translation Dictionary

> ⚠️ **Черновик.** Словарь собран без вычитки редактором-терминологом: применяй как справочник, при расхождении с каноном (`translation-glossary.md` → «Общая таблица») и с готовыми словарями выигрывают они. Спорные ряды помечены «проверить» в комментарии.

Словарь для переводчиков технических статей по наблюдаемости, мониторингу и SRE-практикам: метрики, логи, трейсы, OpenTelemetry, Prometheus и его экосистема, алертинг, SLO, дашборды, профилирование, инцидент-менеджмент. **Не догма** — отражает узус русскоязычного сообщества (переводы SRE Book, Флант, Selectel, OTUS, RU-локализация OpenTelemetry) на 2026 год. Если автор оригинала использует устоявшийся в его команде вариант, и он не противоречит словарю — оставляй авторский.

Базовые SRE-термины (SLO/SLI/SLA, error budget, on-call, postmortem, runbook, MTTR/MTBF, toil, chaos engineering) закреплены в `devops-translation-dictionary` (раздел 12): здесь они повторены буква в букву только там, где без них словарь не читается. Имена продуктов (Prometheus, Grafana, Loki, Tempo, Mimir, Jaeger, Alertmanager) и базовые «метрики / логи / трассировка» согласованы с `k8s-translation-dictionary` (раздел 12).

## Принципы

1. **Русское слово по умолчанию, англицизм — только устоявшийся.** `observability` → «наблюдаемость», `latency` → «задержка», `throughput` → «пропускная способность», `alert fatigue` → «усталость от алертов». Транслитерации «алерт», «дашборд», «спан», «трейс», «лог» — узус техтекста, они первые в своих рядах. «Латентность», «обозреваемость», «журналирование» (вне формального регистра) — не использовать.
2. **Имена продуктов и компонентов — оригинал, не склоняются.** Prometheus, Grafana, Loki, Tempo, Mimir, Thanos, VictoriaMetrics, Jaeger, Alertmanager, Pushgateway, Fluent Bit, Kibana, OpenSearch, Pyroscope. «Прометей», «Графана» — не использовать. Компоненты распределённых систем (Querier, Ingester, Distributor, Compactor) — оригиналом с заглавной.
3. **Идентификаторы в коде и конфигурации — как в коде.** Имена метрик (`http_requests_total`), меток (`job`, `instance`, `le`), полей конфигурации (`scrape_interval`, `group_by`, `receivers`), функций PromQL (`rate()`, `histogram_quantile()`), уровней логирования (`DEBUG`, `ERROR`), состояний алерта в интерфейсе (`firing`) — в backtick, не переводятся.
4. **Типы метрик — по контексту.** В нарративе `counter` → «счётчик», `histogram` → «гистограмма»; `gauge` и `summary` устоявшегося русского не имеют — оригиналом. Как тип в коде (`# TYPE ... counter`) — всегда оригинал.
5. **Аббревиатуры — оригинал.** SLO, SLI, SLA, APM, RUM, OTLP, TSDB, MTTR, MTTD, MTTA, RPS, RED, USE. При первом упоминании допустимо раскрыть сокращение рядом с ним — «RUM (Real User Monitoring)»: это расшифровка аббревиатуры, а не толкование термина. SLO/SLA/SLI — среднего рода: «SLO задано», «SLA соблюдено».
6. **Один термин — один вариант на текст.** Если выбрал «наблюдаемость» — не переходи на `observability` через абзац; если «логи» — не «журналы» в соседнем разделе; если «дашборд» — не «панель» для того же объекта.
7. **При первом упоминании узкого термина — сноска переводчика, не скобки.** В тексте — `baggage[^1]`, `tail-сэмплирование[^2]`; в конце материала — `[^1]: Baggage — пары ключ — значение, которые передаются между сервисами вместе с контекстом трассировки. — Прим. перев.` Дальше — термин без сноски. Три исхода для любого термина: русское слово, оригинал, оригинал со сноской.

| Histogram | гистограмма | Совпадает с databases-словарём |

| Percentile | перцентиль | «99-й перцентиль», «p99»; не «процентиль» |
| Quantile | квантиль | Функция `histogram_quantile()`; перцентиль — частный случай квантиля |
| Tail latency | хвостовая задержка / задержка в хвосте распределения | p99/p99.9; при первом упоминании — сноска переводчика; проверить |

| Staleness | устаревание / staleness | Prometheus: серия без свежих сэмплов считается устаревшей через 5 минут; проверить |

## Раздел 15. Падежные формы (для частых терминов)

### Алерт → алерт

Склоняется как обычное существительное мужского рода: алерт, алерта, алерту, алертом, об алерте. Мн. ч.: алерты, алертов.

### Спан → спан

Мужской род: спан, спана, спану, спаном, о спане. Мн. ч.: спаны, спанов. Если оставляешь `span` латиницей — не склоняй.

### Лог → лог

Мужской род: лог, лога, логу, логом, в логе. Мн. ч.: логи, логов, «в логах». «Журнал» — только в формальном регистре, один вариант на текст.

### Метрика → метрика

Женский род: метрика, метрики, метрике, метрику, метрикой, о метрике. Мн. ч.: метрики, метрик.

### Дашборд → дашборд

Мужской род: дашборд, дашборда, дашборду, дашбордом, на дашборде. Мн. ч.: дашборды, дашбордов.

### Трейс → трейс

Мужской род: трейс, трейса, трейсу, трейсом, в трейсе. Мн. ч.: трейсы, трейсов.

### Prometheus, Grafana, Loki, Tempo, Mimir, Jaeger, Alertmanager

**Не склоняются:** «в Prometheus», «на Grafana», «через Alertmanager». Не «в Прометеусе», не «в Графане». Род при согласовании — мужской для Prometheus, Jaeger, Alertmanager («Prometheus собрал»), женский для Grafana («Grafana показала»).

### SLO, SLI, SLA

**Не склоняются, среднего рода:** «SLO задано», «SLA нарушено», «SLI посчитан» — исключение: SLI часто согласуют по мужскому роду («индикатор»); проверить. Мн. ч. — без изменений: «три SLO», «несколько SLI».

## Раздел 16. Типовые ошибки переводчика

### 1. «Латентность» и «обозреваемость»

```
✗ «Латентность p99 выросла»
✓ «Задержка p99 выросла»

✗ «Обозреваемость системы»
✓ «Наблюдаемость системы»
```

### 2. Смешение «логи» и «журналы» в одном тексте

```
✗ Логи пишутся в JSON. Журналы собирает Fluent Bit. Записи логов попадают в Loki.
✓ Логи пишутся в JSON. Логи собирает Fluent Bit. Записи логов попадают в Loki.
```

### 3. Перевод имён метрик, меток и полей конфигурации

```yaml
scrape_configs:            # НЕ «конфигурации_опроса:»
  - job_name: 'node'       # НЕ «имя_задачи»
    static_configs:
      - targets: ['localhost:9100']   # НЕ «цели:»
```

Имена метрик (`http_requests_total`), меток (`job`, `instance`, `le`) и функций PromQL (`rate()`) — только в backtick и только как в коде.

### 4. «Частота» вместо «скорость» и наоборот

```
✗ «rate() возвращает частоту запросов»      (rate — скорость роста счётчика)
✓ «rate() возвращает скорость роста счётчика» / «число запросов в секунду»

✗ «Скорость ошибок 0,1 %»                    (error rate — доля)
✓ «Доля ошибок 0,1 %»
```

### 5. Калька в SRE-терминах

```
✗ «Скорость сгорания бюджета»     →  ✓ «burn rate» / «скорость расхода бюджета ошибок»
✗ «Командир инцидента»            →  ✓ «руководитель инцидента» / «incident commander»
✗ «Алертная усталость»            →  ✓ «усталость от алертов»
✗ «Бутылочное горлышко»           →  ✓ «узкое место»
```

### 6. «Логгирование» и «инструментация»

```
✗ «логгирование», «залоггировать»    →  ✓ «логирование», «залогировать»
✗ «инструментация кода»              →  ✓ «инструментирование кода»
```

### 7. Склонение имён продуктов

```
✗ «В Прометеусе», «в Графане», «Локи собирает»
✓ «В Prometheus», «в Grafana», «Loki собирает»
```

### 8. «Выборка» вместо «сэмплирование»

```
✗ «Выборка трейсов 10 %»           (sampling — отбор трейсов, не статистическая выборка)
✓ «Сэмплирование трейсов 10 %»
```

### 9. Двойной перевод одного объекта

```
✗ «Дашборд, или панель, показывает…» — «На панели дашборда…»
✓ Выбери один вариант для dashboard («дашборд»); «панель» оставь для panel.
```

### 10. Пассив и «позволяет»

```
✗ «OpenTelemetry позволяет собирать телеметрию»
✓ «OpenTelemetry собирает телеметрию» / «С OpenTelemetry можно собирать телеметрию»

✗ «Алерт может быть заглушён оператором»
✓ «Оператор может заглушить алерт»
```

## Раздел 17. Чек-лист переводчика статьи по наблюдаемости

Перед сдачей литерального перевода пройди по чеклисту:

- [ ] **Канон** — `observability` → «наблюдаемость», `latency` → «задержка», `throughput` → «пропускная способность»; «латентность» и «обозреваемость» — нет
- [ ] **Имена продуктов** (Prometheus, Grafana, Loki, Tempo, Mimir, Thanos, VictoriaMetrics, Jaeger, Alertmanager, Pyroscope, Kibana, OpenSearch, Fluent Bit) — оригинал, не склоняются
- [ ] **Имена метрик, меток, полей конфигурации, функций PromQL** — в backtick, не переведены
- [ ] **Уровни логирования и состояния алертов** (`DEBUG`, `ERROR`, `firing`, `resolved`) — латиницей, как в интерфейсе
- [ ] **Аббревиатуры** (SLO, SLI, SLA, APM, RUM, OTLP, TSDB, MTTR, MTTD, MTTA) — оригинал, расшифровка при первом упоминании; SLO/SLA — среднего рода
- [ ] **Один вариант на текст** — «логи»/«журналы», «дашборд»/«панель», «наблюдаемость»/`observability`, «узел»/«нода» не смешаны
- [ ] **Типы метрик** — `counter` → «счётчик», `histogram` → «гистограмма», `gauge` и `summary` — оригиналом
- [ ] **Узкие термины** (baggage, exemplar, tail-сэмплирование, inhibition) — оригинал или русское слово со сноской переводчика «— Прим. перев.» при первом упоминании, без пояснений в тексте
- [ ] **SRE-термины** совпадают с devops-словарём (error budget, burn rate, on-call, postmortem, runbook)
- [ ] **«Скорость» и «доля»** — rate → «скорость», error rate → «доля ошибок», sampling rate → «доля сэмплирования»
- [ ] **Калек избегли** — нет «является», «позволяет», «осуществляет», «производит», «скорость сгорания», «командир инцидента»
- [ ] **Кавычки** — «ёлочки», внутри — „лапки“
- [ ] **Числа** — `10 000` (пробел), `99,9 %` (запятая, пробел перед %), `5 ГБ`, `100 мс`, `p99`
- [ ] **Атрибуция оригинала** — в конце есть блок «Оригинал: {Title} — {Author}, {date}» + URL

## Раздел 18. Когда термин имеет несколько устоявшихся переводов

Если в русскоязычном сообществе нет единого варианта (например, `observability` → «наблюдаемость» / `observability`, `dashboard` → «дашборд» / «панель», `logs` → «логи» / «журналы»), действуй по приоритету:

1. **Смотри на оригинал.** Если автор пишет разговорно («o11y», «alerts are noisy»), сохраняй тот же уровень формальности в переводе.
2. **Смотри на площадку.** Хабр и инженерные блоги — «алерт», «дашборд», «логи», «скрейпить». Документация и формальные тексты — «оповещение», «панель мониторинга», «журналы», «опрашивать».
3. **Если переводишь в первый раз — бери канонический (первый) вариант словаря:** «наблюдаемость», «задержка», «дашборд», «логи». Второй вариант — осознанный выбор под площадку, не дефолт.
4. **В одном тексте — один вариант.** Это правило важнее любого «правильного» выбора.

## Раздел 19. Что делать с новыми терминами

Если в статье встречается термин, которого нет в этом словаре:

1. **Проверь RU-локализацию документации OpenTelemetry** — https://opentelemetry.io/ru/docs/
2. **Проверь переводы SRE Book и SRE Workbook** на Хабре и русское издание «Site Reliability Engineering. Надёжность и безотказность как в Google»
3. **Поищи в публикациях Фланта, Selectel и OTUS на Хабре** — они переводят статьи Grafana Labs, Prometheus и OpenTelemetry систематически
4. Если нигде нет — оставь **в оригинале**; если термин узкий, при первом упоминании дай сноску переводчика: `Термин[^N]` + `[^N]: Термин — что это. — Прим. перев.` Помета «устоявшегося перевода нет» — в отчёт проверяльщику, не в текст.
