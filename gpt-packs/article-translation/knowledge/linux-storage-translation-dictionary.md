# Linux & Storage Translation Dictionary

> ⚠️ **Черновик.** Словарь собран без вычитки редактором-терминологом: применяй как справочник, при расхождении с каноном (`translation-glossary.md` → «Общая таблица») и с готовыми словарями выигрывают они. Спорные ряды помечены «проверить» в комментарии.

Словарь для переводчиков технических статей по Linux и системам хранения данных: ядро, подсистема памяти, файловые системы, блочный уровень, СХД, распределённые хранилища, резервное копирование и диагностика. **Не догма** — отражает узус русскоязычного сообщества (документация Red Hat / SUSE в переводе, Хабр, opennet.ru, Selectel, Флант) на 2026 год. Если автор оригинала использует устоявшийся в его команде вариант, и он не противоречит словарю — оставляй авторский.

Граница с соседними словарями: контейнеры, Docker и container runtime — `devops-translation-dictionary`; сеть, TCP/IP, туннели, балансировка — `networking-translation-dictionary`; атаки, криптография, IAM, SOC — `security-translation-dictionary`; репликация БД, WAL, PITR — `databases-translation-dictionary`; Kubernetes-хранилище (PV/PVC/StorageClass) — `k8s-translation-dictionary`. Здесь этих терминов нет намеренно — берите их из словаря-владельца.

## Принципы

1. **Имена подсистем, утилит, ФС и проектов — оригинал, строчными как в коде.** `systemd`, `journald`, `udev`, `ext4`, `XFS`, `Btrfs`, `ZFS`, `LVM`, `Ceph`, `MinIO`, `perf`, `strace`, `fio`, `io_uring` — не транслитерируются и не склоняются («в systemd», «через strace», а не «в системдэ», «страйсом»).
2. **Русское слово по умолчанию.** `mount` → «монтирование», `block device` → «блочное устройство», `latency` → «задержка», `lock` → «блокировка», `filesystem` → «файловая система». Англицизм первым — только там, где он реально узус техтекста: «юнит» (systemd), «бэкап», «снапшот» (второй вариант к «снимку»), «таргет» (iSCSI).
3. **Аббревиатуры — оригинал.** IOPS, RAID, LVM, NVMe, SATA, SAS, NFS, SAN, NAS, LUN, OSD, RPO, RTO. При первом упоминании допустимо раскрыть сокращение: «RPO (Recovery Point Objective)» — это расшифровка, а не толкование.
4. **Омонимы решаются по подсистеме.** `namespace` здесь — «пространство имён» (ядро), `target` — «цель» (systemd) или «таргет» (iSCSI), `journal` — «журнал» (ФС и journald), `pool` — «пул» (LVM, ZFS, Ceph). В одном тексте — один вариант на одно значение.
5. **Команды, пути и опции монтирования — в коде.** `mount -o noatime`, `/dev/sda1`, `vm.swappiness` — как в оригинале, в обратных кавычках, без перевода и склонения.
6. **При первом упоминании узкого термина — сноска переводчика, не скобки.** В тексте — `CRUSH[^1]`, `backfill[^2]`; в конце материала — `[^1]: CRUSH — алгоритм Ceph, вычисляющий размещение данных по узлам без центрального каталога. — Прим. перев.` Дальше — термин без сноски. Три исхода для любого термина: русское слово, оригинал, оригинал со сноской.

## Раздел 15. Падежные формы (для частых терминов)

### Unit → юнит

| Падеж | Форма |
|-------|-------|
| Им. | юнит |
| Род. | юнита |
| Дат. | юниту |
| Вин. | юнит |
| Тв. | юнитом |
| Пр. | о юните |

Мн.ч.: «юниты», «юнитов». Типы юнитов — через дефис с оригиналом: «service-юнит», «timer-юнит», «mount-юнит».

### Snapshot → снимок / снапшот

Канонический вариант — «снимок»; «снапшот» допустим в техтексте и склоняется как существительное мужского рода: снапшота, снапшоту, снапшотом. В одном тексте — один вариант.

### Backup → бэкап

Склоняется: бэкапа, бэкапу, бэкапом, о бэкапе; мн.ч. — бэкапы, бэкапов. В клиентских текстах — «резервная копия» (ж.р.), «резервное копирование» (процесс).

### Target → таргет (iSCSI)

Склоняется: таргета, таргету; «iSCSI-таргет» — через дефис. Для systemd-target см. раздел 5 — там вариант не устоялся.

### systemd, journald, udev, Ceph, MinIO, perf, strace, fio

**Не склоняются и не имеют рода.** «Запустить через systemd», «читать журнал journald», «в кластере Ceph», а не «в Цефе», «системдэ», «страйсом». Регистр — как у проекта: `systemd` строчными, `Ceph`, `MinIO` — с заглавной.

### IOPS, RAID, LVM, NVMe, LUN, OSD

Аббревиатуры не склоняются: «100 000 IOPS», «на NVMe», «пять OSD», «два LUN». Составные — через дефис: «RAID-массив», «NVMe-накопитель», «LVM-том», «OSD-узел». Уровни RAID — через пробел: «RAID 10», «RAID 6».

### Filesystem → файловая система

Склоняется как обычное словосочетание; ФС — при повторах: «на ФС ext4», «две ФС». Имена ФС не склоняются: «в ext4», «на XFS», «через Btrfs».

## Раздел 16. Типовые ошибки переводчика Linux/storage-статей

### 1. Кальки вместо устоявшихся терминов

```
✗ «латентность диска»            →  ✓ «задержка диска»
✗ «бутылочное горлышко»          →  ✓ «узкое место»
✗ «отказ страницы»               →  ✓ «страничное прерывание» / «page fault»
✗ «корзина S3»                   →  ✓ «бакет S3»
✗ «разделение мозга кластера»    →  ✓ «split-brain»
```

### 2. Перевод имён подсистем и утилит

```
✗ «Системд перезапустил службу»          →  ✓ «systemd перезапустил службу»
✗ «Прогнали нагрузку через Фио»          →  ✓ «Прогнали нагрузку через fio»
✗ «Данные лежат в Цефе»                  →  ✓ «Данные лежат в Ceph»
✗ «Оптоволоконный канал (Fibre Channel)» →  ✓ «Fibre Channel»
```

### 3. Смешение омонимов

```
✗ «журнал journald» рядом с «журнал ext4» без уточнения
✓ «системный журнал (journald)» и «журнал файловой системы» — разводить при первом упоминании

✗ «цель iSCSI»               →  ✓ «iSCSI-таргет»
✗ «партиция диска»           →  ✓ «раздел диска» («партиция» — только в БД по databases-словарю)
✗ «поток» для process         →  ✓ «процесс» (thread → «поток», process → «процесс»)
```

### 4. Несогласованность вариантов в одном тексте

В одном тексте — один вариант: «снимок» **или** «снапшот», «подкачка» **или** «своп», «бэкап» **или** «резервная копия», «HDD» **или** «жёсткий диск». Не смешивай.

### 5. Склонение несклоняемых

```
✗ «В LVM-е создали том»       →  ✓ «В LVM создали том»
✗ «Проверили страйсом»        →  ✓ «Проверили через strace»
✗ «100 000 иопсов»            →  ✓ «100 000 IOPS»
✗ «на трёх OSD-шках»          →  ✓ «на трёх OSD»
```

### 6. Команды и опции в прозе

```
✗ «смонтируйте с опцией без времени доступа»
✓ «смонтируйте с опцией `noatime`»

✗ «выставьте свопинесс в десять»
✓ «выставьте `vm.swappiness=10`»
```

## Чек-лист переводчика

- [ ] Имена подсистем, ФС, утилит и проектов — оригинал, регистр как у проекта, не склоняются
- [ ] `latency` → «задержка», `throughput` → «пропускная способность», `lock` → «блокировка» (канон)
- [ ] `namespace` в контексте ядра — «пространство имён»; в контексте Kubernetes — по `k8s`-словарю
- [ ] `journal` разведён: системный журнал (journald) ≠ журнал файловой системы
- [ ] `snapshot` — «снимок» / «снапшот», один вариант на текст; согласовано с `databases`
- [ ] Термины резервного копирования (backup, RPO, RTO, restore) — как в `databases`-словаре
- [ ] Ceph-компоненты (OSD, MON, RADOS, CRUSH, PG) — оригинал; узкие (backfill, PG) — со сноской при первом упоминании
- [ ] Команды, пути, опции монтирования и параметры `sysctl` — в коде, не в прозе
- [ ] Аббревиатуры (IOPS, RAID, LVM, NVMe, LUN) — не склоняются; составные — через дефис; RAID-уровни — через пробел
- [ ] Ни одного ряда, помеченного «проверить», не взято в перевод без сверки с редактором или контекстом статьи
- [ ] Контейнеры, сеть и ИБ взяты из словарей-владельцев (`devops`, `networking`, `security`), а не отсюда

## Что делать с новыми терминами

1. **Проверь соседние словари** — `devops` (контейнеры), `networking` (сеть, SAN/NAS), `security` (шифрование, атаки), `databases` (репликация, бэкапы БД), `k8s` (PV/PVC). Если термин там есть — бери оттуда, сюда не дублируй.
2. **Проверь русскоязычную документацию Red Hat / SUSE** (`access.redhat.com/documentation/ru-ru`) и переводы man-страниц — там устоявшиеся варианты для ядра, LVM, systemd.
3. **Поищи на Хабре** (`site:habr.com`) — узус техтекста: транслитерация («снапшот», «ребилд», «тиринг») против русского слова.
4. **Нет устоявшегося перевода** — оригинал + сноска переводчика при первом упоминании (исход C); не придумывай кальку.
5. **Добавь в словарь** с пометкой «проверить» в комментарии — редактор-терминолог снимет пометку при вычитке.
