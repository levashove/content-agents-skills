# Backend Translation Dictionary

> ⚠️ **Черновик.** Словарь собран без вычитки редактором-терминологом: применяй как справочник, при расхождении с каноном (`translation-glossary.md` → «Общая таблица») и с готовыми словарями выигрывают они. Спорные ряды помечены «проверить» в комментарии.

Словарь для переводчиков технических статей по серверной разработке: архитектура сервисов, API, очереди и события, устойчивость, конкурентность, кэширование, фоновые задачи, языки и фреймворки, ORM, тестирование. **Не догма** — отражает узус русскоязычного бэкенд-сообщества (Хабр, русские издания Эванса, Вернона, Фаулера и Ньюмена, документация Go и Spring на русском, HighLoad++) на 2026 год. Если автор оригинала использует устоявшийся в его команде вариант, и он не противоречит словарю — оставляй авторский.

Смежные домены — в соседних словарях, здесь они не дублируются: сеть, HTTP, балансировка и gRPC/GraphQL как протоколы — `networking-translation-dictionary`; транзакции, репликация, шардирование, согласованность — `databases-translation-dictionary`; CI/CD, окружения, мониторинг, feature flags — `devops-translation-dictionary`; аутентификация, JWT, OAuth, CORS, инъекции — `security-translation-dictionary`; фронтенд-часть full-stack-статей — `frontend-translation-dictionary`.

## Принципы

1. **Русское слово по умолчанию.** `thread` → «поток», `queue` → «очередь», `retry` → «повторная попытка», `entity` → «сущность», `value object` → «объект-значение». Англицизм первым — только там, где он реальный узус техтекста: «мьютекс», «горутина», «корутина», «воркер», «мок», «фикстура».
2. **Имена языков, фреймворков, брокеров и библиотек — оригинал.** Go, Java, Spring Boot, Django, FastAPI, Node.js, NestJS, Rust, .NET, Ruby on Rails, Laravel, RabbitMQ, Apache Kafka, NATS, Hibernate, Celery — не переводятся и не транслитерируются («Голанг», «Джанго», «Кафка» — нет). Склоняются только транслитерированные общие термины, имена — нет.
3. **Имена паттернов — переводятся, если перевод устоялся в русских изданиях.** «Ограниченный контекст», «объект-значение», «единый язык», «единица работы», «чистая архитектура», «паттерн Saga». Паттерны без принятого перевода — оригиналом: `outbox`, `event sourcing`, `circuit breaker`, `bulkhead`, `backpressure`, `strangler fig`; при первом упоминании для широкой аудитории — сноска переводчика.
4. **Аббревиатуры — оригинал.** API, REST, CQRS, DDD, ORM, DTO, DAO, DLQ, CDC, TTL, JIT, AOT, JVM, GIL, RPC. При первом упоминании допустимо раскрыть сокращение рядом с ним — «CQRS (Command Query Responsibility Segregation)»: это расшифровка аббревиатуры, а не толкование термина.
5. **Идентификаторы кода — как в коде.** `context.Context`, `WaitGroup`, `@Transactional`, `async def`, `Result<T, E>`, имена HTTP-методов (`GET`, `POST`), имена полей JSON и переменных окружения — в моноширинном формате, без перевода и склонения.
6. **При первом упоминании узкого термина — сноска переводчика, не скобки.** В тексте — `outbox[^1]`, `bulkhead[^2]`; в конце материала — `[^1]: Outbox — паттерн надёжной публикации событий: сообщение сначала пишется в таблицу той же транзакцией, что и бизнес-данные, а затем отправляется в брокер. — Прим. перев.` Дальше — термин без сноски. Три исхода для любого термина: русское слово, оригинал, оригинал со сноской.
7. **Один вариант на текст.** Выбрал «воркер» — не переключайся на «обработчик» через абзац; выбрал `endpoint` — не пиши рядом «эндпойнт».

## Раздел 16. Типовые ошибки переводчика backend-статей

### 1. Concurrency ≠ parallelism

```
✗ «Go поддерживает параллелизм через горутины»   (в оригинале — concurrency)
✓ «Go поддерживает конкурентность через горутины»
```

### 2. «Поток» — три разных слова

```
✗ «Поток читает поток из потока»
✓ «Поток выполнения читает данные из стрима» / «Горутина читает сообщения из очереди»
```

`thread` → «поток», `stream` → «стрим» / «поток данных», `flow` → «процесс» / «сценарий». В одном абзаце — разграничить.

### 3. Склонение имён языков и продуктов

```
✗ «Написано на Питоне», «в Кафке», «на Джанге»
✓ «Написано на Python», «в Kafka», «на Django»
```

### 4. «Сервис» без уточнения

```
✗ «Сервис вызывает сервис через сервис»
✓ «Микросервис заказов вызывает сервис платежей через API-шлюз»
```

В одном тексте разграничить: микросервис (приложение), сервисный слой (класс), Service Kubernetes (объект API).

### 5. Кальки с «является» и «позволяет»

```
✗ «Outbox является паттерном, который позволяет гарантировать доставку»
✓ «Outbox — паттерн, который гарантирует доставку»
```

### 6. Расшифровка вместо термина

```
✗ «Мы используем механизм ограничения потока ошибок»   (circuit breaker)
✓ «Мы используем circuit breaker[^3]»
[^3]: Circuit breaker — паттерн, который перестаёт вызывать сбоящий сервис после серии ошибок и периодически проверяет, восстановился ли он. — Прим. перев.
```

### 7. Перевод идентификаторов кода

```
✗ «Передайте контекст.Контекст в функцию»
✓ «Передайте context.Context в функцию»
```

Имена типов, HTTP-методов, полей JSON, переменных окружения, флагов CLI — как в коде.

### 8. Смешение вариантов

```
✗ «Консьюмер читает топик. Потребитель коммитит смещение. Consumer group…»
✓ «Консьюмер читает топик. Консьюмер коммитит смещение. Группа консьюмеров…»
```

### 9. Английский порядок слов в составных терминах

```
✗ «Архитектура микросервисов», «тестирование контрактов», «ключ идемпотентности запроса»
✓ «Микросервисная архитектура», «контрактное тестирование», «ключ идемпотентности»
```

### 10. Пассив без необходимости

```
✗ «Сообщение будет доставлено брокером как минимум один раз»
✓ «Брокер доставит сообщение как минимум один раз (at-least-once)»
```

## Раздел 18. Когда термин имеет несколько устоявшихся переводов

Если в русскоязычном бэкенд-сообществе нет единого варианта (например, `consumer` → «консьюмер» / «потребитель», `graceful shutdown` → оригинал / «плавное завершение», `coupling` → «связанность» / «зацепление»), действуй по приоритету:

1. **Смотри на оригинал.** Если автор пишет разговорно («goroutines are cheap», «just retry it»), сохраняй уровень формальности: «горутины дёшевы», «просто повтори запрос».
2. **Смотри на площадку.** Хабр и инженерные блоги — «консьюмер», «ретрай», «стектрейс», оригинал для паттернов. Документация и формальные тексты — «потребитель», «повторная попытка», «трассировка стека».
3. **Если переводишь в первый раз — бери канонический (первый) вариант словаря.** Второй вариант — осознанный выбор под площадку, не дефолт.
4. **В одном тексте — один вариант.** Это правило важнее любого «правильного» выбора.

4. **Поищи на Хабре** — `site:habr.com` в заголовках без пояснения: если термин так употребляется, аудитория его знает.
5. Если нигде нет — оставь **в оригинале**; если термин узкий, при первом упоминании дай сноску переводчика: `Термин[^N]` + `[^N]: Термин — что это. — Прим. перев.` Помета «устоявшегося перевода нет» — в отчёт проверяльщику, не в текст.
6. Не придумывай свой перевод — это вносит непоследовательность в экосистему.

Все новые термины, которые встретились в работе, проверяльщик (`translation-verifier`) может предложить добавить в словарь. Решение о добавлении — за оркестратором и редактором-терминологом.
